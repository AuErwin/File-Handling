# 2026-10-27

## 智能文件整理助手（file_organizer）从零开发完成

**技术约束（用户强制要求）**
- Python 3.8/3.9 兼容：禁用 PEP 604（`str | None`）、PEP 585（`list[str]`）、`@dataclass(slots=True)`、
  `Path.is_relative_to()`（3.9+）、`str.removeprefix`。统一使用 `typing.Optional/Union` +
  `from __future__ import annotations`。
- 所有文件 UTF-8；`requirements.txt` 纯 ASCII，禁止中文注释。
- 全程 `pathlib`，禁止 `os.path` 字符串拼接。
- 必须含 `__main__.py`（`from file_organizer.main import main` + `sys.exit(main())`）。

**模块划分（13 个 py 文件）**
`main.py`（argparse 子命令 scan/organize/dedupe/clean/undo/cache）、`scanner.py`（os.walk 生成器 + 手动
`next()` 捕获错误 + rich 进度条 + 排除目录）、`classifier.py`（规则层 + OpenAI 兼容 API 兜底，批次上限 20，
只发文件名）、`duplicate_checker.py`（大小分组 → SHA-256 → rich 表格交互选择，tqdm 进度）、
`cleaner.py`（bottom-up 级联空目录识别 + `█/░` 柱状图）、`executor.py`（`report_20231027_1.pdf` 冲突改名、
大写 DELETE 确认、软删除到回收站、undo 日志）、`undo.py`（反向回放、`_restored_1` 冲突改名）、
`storage.py`（SQLite 缓存，失败降级内存字典）、`config.py`、`models.py`、`utils.py`。

**验证结果（Python 3.9.17 / Windows）**
- 扫描、organize 干跑/实跑、undo 全流程 13 文件还原成功。
- dedupe 交互 + DELETE 确认 + 回收站镜像路径（`<trash>/<批次>/<盘符>/<原相对路径>`）正常。
- clean 识别级联空目录 5 个，柱状图 UTF-8 输出正常。
- 用本地假 OpenAI 接口验证：第 1 次 1 次请求，第 2 次 **0 次请求**（SQLite 缓存命中）。
- 冲突改名实测：`report.pdf` / `report_20261027.pdf` / `report_20261027_1.pdf`。
- 静态检查：无 3.8 不兼容语法（2 处告警均为误报：正则 flag 位或、docstring 文本）。

**踩坑记录**
- Git Bash 中 `/tmp` 传给 Windows 原生 Python 会被解析为 `C:\tmp`，测试脚本必须用 `os.environ['TEMP']`
  拼 Windows 原生路径。
- rich 渲染用户路径必须 `rich.markup.escape`（`中文 文件 [测试].bin` 里的 `[...]` 会被当标签解析）。
